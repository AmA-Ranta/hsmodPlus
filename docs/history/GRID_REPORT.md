## 本轮修掉的缺陷

1. **停止评估被登录/加载分支吞掉**：停止请求在客户端启动阶段（“等待收藏加载”）到达时，MonitorTick 先进入登录等待分支 return，永远到不了完成判定。→ 新增顶层 `TryFinishPendingStop()`，在一切登录/启动等待之前评估停止契约。
2. **启动阶段 API 探测为 null，导致停止无法确认脚本关闭**：把进程身份读取包进安全包装，身份读取异常不再让整个状态探测返回 null；探测超时 900ms→2500ms。
3. **无 activity 文本时的边界判定**：脚本已关闭 + 原生日志无进行中对局标记时，视为启动/空闲安全边界（仍要求脚本 off 持续 ≥15 秒），停止在 16–22 秒内完成。
4. **界面文案**：停止等待由“等待当前对局结束”改为“等待对局结算或空闲边界”，与实际语义一致。

## 网格过程中发现的环境问题（已修）

- 重复中控进程导致状态互串/假超时 → 执行器改为提权杀进程 + 启动前确认单实例，否则记 `ENV_ERROR`。
- 历史日志被当成新事件 → 执行器改为记录起始行号、只匹配新增日志。

## 已修复：停不下来的“等待当前对局结束” + “HsMod 状态暂不可读”

- **现象**：对局早已结束/客户端在加载，界面卡在“等待当前对局结束”；同时 `脚本：HsMod 状态暂不可读` 长期不恢复。
- **根因 1**：状态探针的单飞锁只在 `BeginInvoke` 回调里释放；回调一旦未被消息泵处理，锁永远为 1，之后每 8 秒的探测全部被跳过 → `_hsModStatus` 永久为 null。
- **根因 2**：停止完成判定放在登录/启动等待分支之后，客户端启动阶段（“等待收藏加载”）会提前 return，永远到不了完成判定。
- **修复**：
  1. 探针结果先写入后台字段并**在后台线程必定释放单飞锁**，UI 线程每次刷新时消费结果（`ApplyPendingProbeResult`）；
  2. 停止判定提升到 `MonitorTick` 顶部（`TryFinishPendingStop`），先于一切登录/启动等待；
  3. 脚本 off 证据增加日志侧兜底（API 不可读时用 `IsConstructedScriptEnabled()`），并对“无 activity + 无已知进行中对局”的启动边界判定为安全；
  4. 状态文案：“等待当前对局结束”→“等待对局结算或空闲边界”。
- **验证**：同一客户端、同一 API 下，界面由 `HsMod：状态暂不可读 / 脚本：未检测到开启` 变为 `脚本：HsMod 已连接，脚本未开启　HsMod：脚本关闭`（截图 `artifacts/ui-probe-fixed.png`）；网格 8 个 cell 停止耗时 6–22 秒，未再出现卡死。
