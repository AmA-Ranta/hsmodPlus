# 中控 UI 设计规范（WPF-UI · 紧凑双页）

界面层为独立 WPF 工程 `ArenaController.Wpf`，WPF-UI（Fluent 2）浅色主题；引擎 `hsmodPlus.Core` 保留全部控制逻辑。目标：**一屏看全，不空旷，不做外部设计稿复刻。**

## 1. 结构（两页）
- 左侧窄导航（150px）：控制台 / 运行日志；底部固定版本与作者。
- 控制台页：从上到下
  1. 运行状态块：整体状态 + 炉石/盒子/插件/心跳/接管时间 + 天梯统计 + 最近结果/段位/时间 + 当前卡组。
  2. 通用任务（天梯 / 狂野 / 休闲 / 酒馆战棋）：模式、卡组名称、**对局数**（0=不限）、启动前等待盒子心跳、每日计划（启用/开始/停止）。
  3. 竞技场（独立统计，浅紫底色区分）：类型、**每轮对局 / 总局 / 最多轮数**、门票不足停止、金币不足停止、本轮结束后停止；仅竞技场模式生效。
  4. 底部并排：停止策略（停止后关闭炉石、掉线/卡住自动恢复）与安装维护（路径、安装/修复插件、还原原版、探测路径、版本保留说明）。
- 运行日志页：只读等宽日志。
- 页脚：设置状态 + 应用设置。

## 2. 语义约定
- 天梯/狂野/休闲/酒馆战棋只有「对局数」；不出现轮数概念。
- 竞技场独立：轮次、每轮局数、门票/金币保护、本轮边界只出现在竞技场块。
- 门票/金币停止不再放入通用停止策略。
- 竞技场统计与天梯统计分开显示（引擎分别读取两套台账）。

## 4. 交互与数据
- 设置仍是暂存模型：修改后页脚提示“已暂存”，点「应用设置」才下发；对局中排队到本局结束。
- 数据全部来自引擎真实状态与台账，不做演示数据。
- 模式切换时通用“对局数”与竞技场额度区自动置灰/启用，避免混淆。

## 5. 工程
`ArenaController.Wpf` → `ControllerHost` → `ArenaController`（hsmodPlus.Core）。构建：`tools/BuildWpfRelease.ps1`；回归：`tests/ControllerModeStats`。
